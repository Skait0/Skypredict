# 1xBet Nigeria: the fifth bookmaker

Date: 29 Sep 2026. Branch `onexbet` in both repos (site: Skypredict; booking
service: soccerwizard-api). Merges before the `accounts` branch.

## Why

The owner picked 1xBet as the fifth book, to add before login goes live. The
owner confirmed that 1xBet is licensed in Nigeria.

## What was measured (read-only, 29 Sep 2026)

All of this came from 1xbet.ng itself. The details are in memory
`onexbet-bookie-feasibility.md`.

| Question | Answer |
|---|---|
| Access | Plain fetch gets a Cloudflare 403. A curl_cffi `impersonate="chrome"` session that first GETs `/en/line/football` gets JSON. We never solve a challenge. |
| Feed | `LineFeed/GetChampsZip` (about 250 competitions, 11+ days ahead), then `GetChampZip?champ=` (games only, no prices), then `GetGameZip?id=` (the card, about 1,100 outcomes on a big game). |
| Sportradar id | None on the card. Pair by name and kickoff only. |
| Booking | `POST LiveBet/Open/SaveCoupon`, with the exact body their site sends (`Kind:3`, `Vid:1`, `CheckCf:1`, `partner:159`). |
| Read-back | `POST LiveBet/Open/GetCoupon {"Guid":code}` returns names, league, kickoff, `MarketName`, `Param` and the LIVE `Coef`. |
| Deep link | `https://1xbet.ng/en?coupon-code=CODE` loads the slip (checked in a browser). |
| Betslip cap | 50. At 51 they refuse with ErrorCode 157972. |
| Same-game legs | SaveCoupon accepts them, but their betslip marks both legs "Incompatible event". We treat them as refused. |
| Price check | None. Coef 99 was accepted, and the read-back reprices the leg. |
| Silent failures | A bogus Type still mints a code, and that code reads back as "finished". 30 legs read back as 29 with no error. The read-back leg count is mandatory. |
| Brand | Icon #276BA6 on #FFFFFF; logo accent #14A0FF; font Roboto / Roboto Condensed. |

## Design

### Booking service: `soccerwizard-api/onexbet.py`

It has the same surface as `betpawa.py`. No route branches on which book it
is talking to.

- `all_fixtures()` is the sweep. It reads GetChampsZip, then GetChampZip for
  each competition, then GetGameZip for each game, on a 45-minute timer.
  Requests go one at a time with a 0.45s pause. The deadline is sized to the
  per-card cost, so the plan measures how far the sweep reaches before it
  fixes the page count (see Open questions). It drops SRL, eSoccer, cyber and
  virtual events before anything else. It refuses a sweep that returns less
  than a sane fraction of the last good board.
- The row shape is the same as the other books: `eventId, slotId, teams,
  kickoff (ISO UTC), league, country, odds, raw, sel`. `srId` is always None.
  The new field is `sub`: `{"1st half": gid, "2nd half": gid, "Corners": gid,
  "Corners|1st half": gid, ...}`, read from the card's `SG`.
- The market key is `(period, T, P)`. `P` is None for single-row markets.
  Their G is not part of the key, because T is unique inside a period.
- `build_selection(event, code)` resolves the period's GameId from `sub`
  (the main id for full time). It returns their Events element with
  `Kind:3`.
- `generate_code(selections)` works in this order:
  1. It refuses more than 50 legs.
  2. It refuses a second leg on the same game, naming it. The game is keyed on
     the MAIN game id, so a first-half leg and a full-time leg on one fixture
     also clash.
  3. It mints the code.
  4. It reads the code back. A leg-count mismatch is our error, not a
     bookmaker refusal. It returns the read-back's own total price.
- `read_coupon(code)` returns the shared contract, `{legs:[{eventId,
  prediction, raw, home, away, league, kickoff, odds}], available, booked}`.
  It decodes each leg through the reverse of the forward table.
- `market_for(code)`, `reason_uncarried(code)` and `NOT_CARRIED` follow
  betpawa.py.

### Market tables

- `MARKET_MAP` holds the modelled dozen codes, mapped by hand from the
  catalogue and then verified by read-back `MarketName`: 1/X/2 (T1-3),
  1X/12/X2 (T4/5/6, note that 5 is 12), OVER/UNDER x.5 (T9/10), GG/NG
  (T180/181), FH_OVER_0.5 (1st half T9 P0.5), HOME/AWAY over/under (T11-14),
  and the unders.
- `PASSTHROUGH_MAP` is GENERATED by `tools/xbgen.py`, which is modelled on
  `bpgen.js`. It proposes each of our codes in 1xBet's words
  (period + MarketName template + P). It keeps a proposal only if the
  outcome is priced on one of the 8 deepest cards. It checks the handicap
  sign against the prices inside one card. It writes the rejects grouped by
  family with a reason each, and those become `NOT_CARRIED`. The harvest
  script (`xbharvest.py`, in the scratchpad now) moves into `tools/`.
- Semantic traps to rule on in the generator, not by position:
  - G2 "Handicap" with whole lines is two-way and pushes, so it is Asian whole
    balls, not European.
  - G27 is the European three-way handicap.
  - G136 correct score encodes P as `home + away/1000`.
  - G9939 / G3309 exact-goal rungs end at "2 or more" in the halves.
  - "Next Goal" P=1 is the first goal.

### Service wiring (`server.py`)

- Add a `_ONEXBET_CACHE`, a refresh thread and a lock, the same as betPawa.

- `public/index.html`:

  - Add the skin class `xb`, which is free in the page.

  `api/tg.js` (ORDER, the `/start` deep-link regex, the welcome copy) and

- Tests: `test/books.js` stubs, the proxy allowlist, the cache-policy table,

  is updated.

### Brand

- The accent is #276BA6 on dark, which passes contrast on the dark ground,
  checked in a test. The light theme uses the same blue, and the test checks
  it against white. The wordmark is "1XBET" in Roboto Condensed, bold and
  italic, with a local stack and no webfont link.
- A test pins both colour values.

## Testing

- Python (`test_onexbet.py`):
  - `market_for` never falls back to a default.
  - The reverse lookup is derived from the forward table.
  - Every code another book carries is either mapped here or excused in
    `NOT_CARRIED`.
  - The cap refuses 51 legs.
  - A same-game pair is refused with the leg named.
  - A read-back count mismatch returns an error.
  - Fixtures are recorded from live responses.
- Node: extend the existing enumerations (books, proxies, cache policy, label
  coverage, font-family validity). Each new test gets one mutation check.
- By hand, on the deployed preview:
  1. Run `scripts/namesaudit.js`.
  2. Take a real 1xBet code. Read it, convert it both ways, split, edit and
     merge it, then book a board slip.
  3. Confirm the deep link opens.
  4. Confirm the daily code mints on the next run.

## Out of scope

Live (in-play) betting, player props, and accounts/login, which stay on their
own branch.

## Open questions

- How long the sweep takes, which sets the page count. It is 1 + C + G
  requests at 0.45s each. If a full card per game is too slow, sweep only the
  modelled groups. If that is not possible, sweep cards only for fixtures on
  the board. The plan measures this first.
